how to configure linux kernel for qemu

Configuring a Linux kernel specifically for running inside QEMU (as a virtual machine or for fast debugging) requires enabling the right hypervisor drivers, serial console support, and essential file system options while stripping out unnecessary hardware drivers.

Here is a step-by-step guide to building a lightweight, fast-booting Linux kernel for QEMU.

1. Start with a Clean Configuration
Start from your architecture’s base configuration, or use defconfig to get a working baseline.

Bash
# Clone the kernel source (or use an existing source tree)
git clone https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git
cd linux

# Generate baseline config (x86_64 example)
make x86_64_defconfig

# Launch interactive menu configuration
make menuconfig
2. Essential Kernel Configuration Options
Ensure the following options are set inside make menuconfig (or directly in .config):

A. VirtIO Drivers (Crucial for QEMU I/O Performance)
VirtIO drivers allow the guest kernel to communicate directly with QEMU, providing high-performance virtualized disk, networking, and devices.

CONFIG_VIRTIO_MENU=y

CONFIG_VIRTIO_PCI=y (VirtIO over PCI bus)

CONFIG_VIRTIO_BALLOON=y (Dynamic RAM management)

CONFIG_VIRTIO_INPUT=y (Keyboard/Mouse)

CONFIG_VIRTIO_CONSOLE=y (Virtio serial console)

CONFIG_NET_9P_VIRTIO=y & CONFIG_9P_FS=y (For sharing host folders via 9p)

B. Virtual Storage & Block Devices
CONFIG_BLK_DEV=y

CONFIG_VIRTIO_BLK=y (VirtIO hard disk support)

CONFIG_SCSI=y & CONFIG_SD_BOOT=y

CONFIG_SCSI_VIRTIO=y (VirtIO SCSI controller support)

C. Networking
CONFIG_NET=y

CONFIG_INET=y

CONFIG_NET_CORE=y

CONFIG_VIRTIO_NET=y (VirtIO network adapter)

D. Serial Console (For CLI & Debugging Output)
To see boot logs in your terminal without needing a GUI window, enable serial tty drivers:

CONFIG_SERIAL_8250=y

CONFIG_SERIAL_8250_CONSOLE=y

CONFIG_SERIAL_CORE=y

CONFIG_SERIAL_CORE_CONSOLE=y

E. Root Filesystem Support
Enable support for whichever filesystem your rootfs image uses:

CONFIG_EXT4_FS=y (Standard ext4 disk images)

CONFIG_BLK_DEV_INITRD=y (If using an initramfs/initrd)

CONFIG_DEVTMPFS=y & CONFIG_DEVTMPFS_MOUNT=y (Auto-mount /dev at boot)

3. Minimal Target Config via kvmconfig
If you want an optimized configuration without manually editing options, Linux provides a shorthand fragment tailored specifically for KVM/QEMU:

Bash
make x86_64_defconfig
make kvmconfig
Note: make kvmconfig (or make xenconfig) enables all mandatory VirtIO, serial, and KVM guest drivers automatically.

4. Build the Kernel
Build the kernel image (and modules if any were configured):

Bash
# Build using available processor cores
make -j$(nproc) bzImage
The compiled kernel binary will be located at:
arch/x86/boot/bzImage (for x86_64) or arch/arm64/boot/Image (for ARM64).

5. Booting the Kernel in QEMU
Run your newly compiled kernel in QEMU using the following command structure:

Bash
qemu-system-x86_64 \
  -enable-kvm \
  -cpu host \
  -m 2G \
  -kernel arch/x86/boot/bzImage \
  -drive file=rootfs.img,format=raw,if=virtio \
  -append "root=/dev/vda rw console=ttyS0 quiet" \
  -nographic
Key Flag Explanations:
-enable-kvm: Uses host CPU hardware virtualization.

-kernel: Points directly to your compiled kernel binary.

-drive ...,if=virtio: Attaches the disk image via VirtIO_BLK (appears as /dev/vda in guest).

-append "console=ttyS0": Redirects kernel outputs to the current terminal window (-nographic).
